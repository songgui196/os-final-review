# 第 12 章 保护和安全

**位置：** 书 p.360–386 / PDF 381–407。**层级：** 全书备查；以教材的防护目标和机制分类理解。

## 核心框架：目标—身份—权限—机制

**安全目标**是数据机密性、数据完整性、系统可用性。保护机制服务于这些目标：先辨认“你是谁”（验证/认证），再判断“你能做什么”（授权/访问控制），执行时不可绕过检查，还要保留适当审计。验证成功不是无限权限。

| 小节 | 提炼的模型 | 怎样使用 |
|---|---|---|
| §12.1 安全环境 | 机密性、完整性、可用性；物理、逻辑与管理维度 | 按被破坏的目标区分泄漏、篡改、拒绝服务；同时看运行环境 |
| §12.2 加密 | 对称/非对称、数字签名、数字证明书 | 加密保护内容可读性；签名支持来源与完整性验证；证明书绑定身份与公钥 |
| §12.3 用户验证 | 口令、物理标志、生物识别等 | 区分知识/持有/固有特征与各自的失效方式，组合机制时注意管理与撤销 |
| §12.4 内部攻击 | 逻辑炸弹、陷阱门、木马、登录欺骗、缓冲区溢出等 | 用触发条件和受破坏边界分类，再分析最小权限、输入检查、隔离、审计如何减损 |
| §12.5 外部攻击 | 病毒、蠕虫、移动代码及预防检测 | 区分附着宿主与传播方式；防护依赖检测、控制执行、更新与恢复，多层处理 |
| §12.6 可信系统 | 访问矩阵、信息流控制、可信计算基 TCB | 既看直接访问，也看数据能流向何处；识别必须信任的最小组件集合 |

## 精确区分常见概念

对称加密共享密钥，适合内容加密但要解决密钥分发；非对称机制使用成对密钥，可支持密钥建立、签名等不同操作。**不能把所有公钥系统都概括为“随便用私钥加密再公钥解密”。** 学习本章重在功能与信任关系，而非凭概念自行实现密码算法。

数字签名不自动保密；把报文和签名明文发出，仍可能让第三人读懂，但可验证来源和是否被改。证书也不是保证某应用行为无害，关键在证书链、名称、有效性与使用场景的验证。

访问矩阵按保护域与对象列权限，信息流模型另约束标签之间允许的流向；前者问“能否读/写这个对象”，后者问“这份信息能传到哪里”。两者不完全互相替代。

## 设计原则（§12.6.3，书 p.384–385 / PDF 405–406）

教材列六项：**微内核原则、策略与机制分离原则、安全入口原则、隔离原则、部分硬件实现原则、分层设计原则**。使用时分别问：可信核心能否缩小；可变授权规则能否与执行机制分开；敏感访问是否都经过受控入口；用户/组件能否隔离；硬件是否强制关键边界；分层能否减少交叉信任。安全内核与前文的微内核有关，但并非两个名称的完全同义替换。

## 演练（自拟）

用户通过口令验证，但普通进程无权读取另一用户私有文件。系统调用执行权限检查并拒绝请求，是保护机制阻止了机密性被破坏；“已登录”不能越过文件权限。若数据被允许读取后复制到公共输出，还要用信息流/策略视角判断泄漏，单看原文件的读权限不足以回答所有问题。

## 自测与关联

能把攻击影响对应三目标、区分认证/授权、加密/签名、访问控制/信息流；能解释可信计算基越复杂越难全面确认正确，但“小”本身不自动等于安全。文件保护见[第 8 章](ch08-files.md)，用户/内核模式边界见[第 1 章](ch01-introduction.md)。
