# 第 1 章 操作系统引论

**位置：** 书 p.1–38 / PDF 22–59。**大题落点：** OS 特征；相关 I/O 与处理机基础。

## 核心问题与判断框架

操作系统向下管理处理机、内存、设备、文件等资源，向上提供抽象和服务。回答“是什么”从两侧组织：**资源管理者**说明如何分配和保护；**用户与硬件间接口/扩展机器**说明程序不必直接控制每个硬件细节。目标常从方便性、有效性、可扩充性、开放性写，目标与实际管理功能分开。

## 四特征：定义 + 关系 + 例子

- **并发**在同一段时间推进多个活动；**并行**在同一时刻真的同时执行。单核交替运行可有并发，多核是实现并行的一种硬件条件。
- **共享**是多个并发活动使用系统资源，包括互斥共享和在一段时间内的同时共享。一个打印机可轮流输出多个进程的文件，但不能不加管理地把两个输出流交叉。
- **虚拟**是用时分/空分等机制构造逻辑资源。CPU 分时让多个进程各自看似拥有执行机会；虚拟存储把逻辑空间和实际驻留容量分开。
- **异步**指实际执行推进速度和交替时机不确定，原因包括调度、I/O、资源等待、中断。正确同步约束的结果不能因此失控。

并发导致资源共享需求，共享需要有序管理才能支撑并发，两者互为条件。虚拟有助于复用和隔离资源，异步体现了进程在此环境中的推进方式。见[简答模板](../short-answers.md#1-操作系统的特征)。

## 机制与策略的思维方式

发生“能不能做”时先问硬件和内核机制，发生“选谁/何时做”时再问策略。例：时钟中断提供重新获得 CPU 控制权的机会，RR 规定用完时间片后让谁运行。原语保证操作不可被有关并发活动破坏地分割；并不等于任何 C 语言一行都是原子，也不等于在多核只关闭本核中断就能解决全部互斥。

**内核态/用户态：** 限制特权操作防止用户程序破坏系统。系统调用、中断或异常进入内核处理，返回后恢复执行；一次模式切换不必切换到另一个进程。外设中断和指令执行引发的异常来源不同，系统调用通常经由特定陷阱类入口请求服务。

**结构取舍：** 分层便于验证层次依赖，但可能有跨层开销；微内核将少量基本机制留在内核，许多服务移到用户态，有隔离和扩展优势，也可能增加通信成本；外核强调保护性地复用硬件，让更高层软件决定抽象。不要把这些名称当作系统性能的绝对排序。

## 演练：CPU 和 I/O 为什么能重叠（自拟）

A 先算 3，再 I/O 4，再算 1；B 只算 4。两者 0 时刻就绪，单 CPU，独立设备，忽略切换。串行总时间 `3+4+1+4=12`；让 A 在 `[0,3)` 计算、`[3,7)` 做 I/O，同时 B 在 `[3,7)` 计算，最后 A `[7,8)`，总 8。CPU 没有同刻执行 A、B，但仍通过并发减少等待。
