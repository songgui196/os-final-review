# 第 11 章 虚拟化和云计算

**位置：** 书 p.340–359 / PDF 361–380。**层级：** 全书备查；与 OS 的“虚拟”特征建立联系。

## 核心框架：谁提供抽象，谁保持控制

虚拟化在硬件和客户机之间增加软件层，向客户机呈现可运行的逻辑机器；VMM（虚拟机监视器/管理程序）管理物理资源并隔离客户机。云计算还把资源供给变成经网络可获取、可计量和弹性调整的服务，不能把“装了几台虚拟机”当成完整云服务。

## 架构和实现（§11.1–11.2）

| 层面 | 机制 | 取舍与风险点 |
|---|---|---|
| Type 1 / 裸金属 | VMM 直接在硬件上管理客户机 | 控制路径较直接；仍需设备与管理支持 |
| Type 2 / 寄居 | VMM 借助主机 OS 运行 | 部署和设备利用便利；多一层依赖与路径 |
| CPU 虚拟化 | 普通指令尽量直接执行，敏感操作由 VMM 处理；可用翻译、半虚拟化或硬件辅助 | 传统陷入执行模型需处理不能正确陷入的敏感指令；不同技术假设不同 |
| 内存虚拟化 | 管客户虚拟、客户物理到机器物理的映射，如影子页表或硬件辅助转换 | 兼顾隔离和转换开销；“客户物理”并非最终机器物理 |
| I/O 虚拟化 | 模拟设备、配合的虚拟驱动或直接分配等 | 通用兼容、性能与隔离/迁移能力需权衡 |
| 多核虚拟化 | vCPU 映射并调度到物理 CPU | vCPU 数不等于任意时刻独占的核心数 |

**阅读教材的边界：** §11.1.3–11.1.4 的敏感指令/特权指令讨论解释传统架构为何要特殊处理。它针对所述架构与实现年代，不能把“早期 x86 不满足某传统陷入条件”推广成“所有 x86 永远不能虚拟化”。复习机制时标清前提。

## 云计算五特征与服务层次（§11.3）

教材列 **按需自助服务、无处不在的网络访问、共享资源池、快速弹性、服务可计量**。判断一个案例要逐项找证据，不能用“服务器在机房”代替它们。

**IaaS**提供基础计算/存储/网络资源；**PaaS**提供应用运行与部署平台；**SaaS**提供完成的应用服务。分层回答“用户管理什么、提供方管理什么”，避免把租一台虚拟机和使用在线应用说成同一控制范围。虚拟机迁移可分 P2V、V2V、V2P；热/在线迁移要在传内存等状态时协调最后切换，不能只复制磁盘文件就声称保存了运行状态。授权与检查用于限制客户/管理操作以及观察状态。

## 演练（自拟）

一台 8 核物理机给两台客户机各配 8 vCPU。问能否各自持续得到 8 核算力：不能仅据 vCPU 个数保证；VMM 在共享物理资源上调度，必须看负载、配额与超额配置。若应用遇到延迟，先区分等待物理 CPU、客户机自身调度、内存换页和 I/O，不能把任何慢都归因于“虚拟机不真实”。

## 易错、自测与关联

虚拟机、虚拟存储器、进程是不同层面的抽象；一个客户机也有自己的页表与进程。§11.4 的虚拟机软件是教材实例，不作为最新产品推荐。能画 Type 1/2 的层次，区分客户物理与机器物理，列五个云特征即可建立本章框架。基础见[第 1 章虚拟](ch01-introduction.md)、[第 5 章地址映射](ch05-memory-management.md)。
