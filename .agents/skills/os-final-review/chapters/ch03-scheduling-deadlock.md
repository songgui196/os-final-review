# 第 3 章 处理机调度与死锁

**位置：** 书 p.73–108 / PDF 94–129。**大题落点：** 调度简答、进程调度计算、银行家算法。

## 调度：分离层次、时机与策略

三级调度用三个问题记：**高级**决定后备作业接纳谁；**中级**决定哪些进程换出/换入；**低级**从就绪者中选谁获得 CPU。低级最频繁，需控制开销。进程调度包含保存当前 CPU 现场、选择新进程、由分派机制恢复现场并移交控制。

非抢占方式保留运行者直至完成/阻塞等主动或必需的交接；抢占可依优先级、短剩余进程、用片等原则进行。批处理重吞吐量/周转，分时重响应/公平，实时重截止时间/可预测性。

| 算法与场景 | 选择规则 | 得益与代价 |
|---|---|---|
| FCFS | 就绪入队先后 | 简单；短任务可能受长任务拖累 |
| SJF / 短进程优先 | 已就绪者中预估执行最短 | 常能改善平均等待；长任务可能饥饿，执行量需估计 |
| 优先级 | 静态或动态优先级；方向按题设 | 区分紧急性；低优先级可饥饿，可用老化缓解 |
| RR | 按队列给片，未完回尾 | 公平且响应较好；片太小切换开销高，太大近似 FCFS |
| 多级队列 | 类型分队列、各队列策略不同 | 适合不同服务类别；固定分组可能不适应行为变化 |
| 多级反馈队列 | 多队列、不同优先级与时间片，运行行为决定升降 | 兼顾交互和批处理；仍需明确提升、降级和抢占规则 |
| 公平/保证调度 | 按历史获得 CPU 的份额等纠偏 | 关心分配比例，不等于简单轮转 |

**不要混淆 SJF 与 SRTF：** 新短任务到达时，非抢占 SJF 不立即打断；SRTF 会与当前**剩余**时间比较。求周转先算 `完成−到达`，带权再除自己的服务时间。详见[习题 3 第 19–21 题](../exercises/01-cpu-scheduling.md)。

## 实时调度与 Linux 实例

- **EDF（最早截止时间优先）**按截止时刻，**LLF（最低松弛度优先）**按 `截止−当前−剩余执行`。剩余量变化会改变松弛度，不能只按任务编号静态排序。
- **优先级倒置**：高优先级等低优先级持有的锁，中优先级又拖住低者；优先级继承让持锁者临时获得等待者的较高优先级以尽快完成关键工作。
- §3.4 的 Linux 调度是教材实例，需结合该实例时代和上下文学习。它用于说明就绪结构、公平性等设计取舍，不作为当前系统实现版本说明。

## 死锁：四条件，四种处理方向

| 必要条件 | 意义 | 可对应的预防措施 |
|---|---|---|
| 互斥 | 某资源排他使用 | 能共享时改造为共享；不是所有资源都可取消排他 |
| 请求和保持 | 持有一些资源又等待其他资源 | 预先一次申请，或申请失败先归还已持资源 |
| 不可抢占 | 已获资源不能被强制取回 | 合适资源允许回收/重试；不适用于不可恢复的外设操作 |
| 循环等待 | 多进程形成资源等待环 | 全局资源编号，按固定顺序加锁 |

四条件同时成立是死锁的必要条件。资源分配图有环：若相关每类资源只有一实例，环意味着死锁；多实例资源时有环不必已死锁。**死锁**是互相等待、靠彼此才能推进；**饥饿**是长期被其他任务挤掉。不要把“很久没运行”一律判成死锁。

- **预防**从结构上破坏条件，限制较强。
- **避免**知道最大需求，以试分配和安全性检查防止不安全状态；银行家算法是本次主线。
- **检测**允许发生、用实际待请求判断能否完成；**解除**终止进程、回收资源或回滚恢复。
- **安全状态**存在一种顺序能让全部进程在满足最大需求后结束；不安全只是缺少保证，不直接等同于已死锁。
