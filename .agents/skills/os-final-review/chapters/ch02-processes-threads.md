# 第 2 章 进程的描述与控制

**位置：** 书 p.39–72 / PDF 60–93。**作用：** 为调度、同步简答提供状态与实体基础。

## 核心思路

程序是静态指令与数据；进程是程序的一次执行活动，具有动态性、并发性、独立性、异步性等特点。用 **PCB（进程控制块）+程序+数据** 描述进程实体；PCB 记录标识、状态、CPU 现场、调度与资源等信息，是内核管理和切换进程的依据。一个程序可对应多个运行实例，不能将代码文件和进程一一等同。

## 状态转换：先看等待的是什么

| 原状态 → 新状态 | 触发 | 判断要点 |
|---|---|---|
| 就绪 → 运行 | 被分派 CPU | 已有除 CPU 外必要条件 |
| 运行 → 就绪 | 用片完、被抢占、主动让出等 | 不代表等 I/O |
| 运行 → 阻塞 | 等事件、I/O、资源或同步条件 | 此时即使给 CPU 也不能直接继续 |
| 阻塞 → 就绪 | 所等条件出现、被唤醒 | 不通常直接进入运行 |
| 创建 → 就绪；运行 → 终止 | 创建完成、执行结束等 | 实现细节可能另有过渡 |

挂起是系统把进程暂停并可能置于外存，以控制负载或内存；阻塞是缺执行条件。二者可组合：阻塞挂起的进程事件完成后可变为就绪挂起，仍需激活后才能入内存竞争 CPU。中级调度处理这类换入换出，不能替代低级调度。

## 前趋、原语和通信

- **前趋图：** 顶点是活动，有向边 A→B 表示 B 要在 A 完成后才能执行。用它找并发机会，保留依赖边，不能把所有节点强行串行。前趋图无环；含循环的等待图则是另一种分析对象。
- **控制原语（§2.3）：** 创建分配标识与 PCB、初始化并接入有关队列；终止回收资源；阻塞保存状态并切队列；唤醒恢复就绪资格。原子性避免状态改了一半就被其他执行流观察到。
- **通信（§2.4）：** 共享存储交换数据但需同步；消息传递用 send/receive 接口；管道有容量和读写约束；信号、消息队列、信号量、套接字等适用场景不同。信号与信号量不是同一个东西。

## 线程与实现模型（§2.5–2.6）

引入线程后，通常把**进程**作为资源分配和保护单位，把**线程**作为执行与调度单位。共享进程地址空间的线程有各自 PC、寄存器、栈与执行状态；共享不代表所有线程状态相同。

| 方案 | 管理与可见性 | 优缺点 |
|---|---|---|
| 用户级线程 ULT | 用户线程库管理，内核可能只见进程或少量内核实体 | 切换可较轻；多对一中一个内核阻塞可能挡住同组 ULT，无法靠这一内核实体实现多核并行 |
| 内核支持线程 KST | 内核可识别并分别调度 | 可让其他线程运行并利用多个 CPU；管理和切换开销相对较大 |
| 多对一 / 一对一 / 多对多 | ULT 到 KST 的映射关系 | 分别取简洁、充分内核调度能力、灵活复用；不是线程状态的数量 |

## 演练（自拟）

A 运行后申请磁盘读：A 转阻塞，B 就绪被调入运行。磁盘完成中断使 A **就绪**；若系统非抢占，B 继续到阻塞或结束；若策略允许 A 抢占才切换。说明“条件完成”“重新选择”“现场切换”是有关但不同的动作。

## 自测与避错

- 看见“缺少 CPU”写就绪；看见“缺少数据/资源”写阻塞；看见“被换出”再考虑挂起。
- 一个进程内线程能同时运行，并不代表可不加锁地修改同一计数器。
- 解释“唤醒不是马上运行”“模式切换不是必然进程切换”，再去做[第 3 章调度](ch03-scheduling-deadlock.md)与[第 4 章同步](ch04-synchronization.md)。
