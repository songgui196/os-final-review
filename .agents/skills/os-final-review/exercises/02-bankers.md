# 计算题 2：银行家算法

**教材定位：** §3.7.1–3.7.2（书 p.99–102 / PDF 120–123）；习题 3 第 22 题（书 p.107 / PDF 128）。

## 题干分两类

1. **给当前分配，问安全性。** 算 `Need=Max−Allocation`，设 `Work=Available`，每次找一个尚未完成且各分量 `Needᵢ≤Work` 的进程。模拟它完成，`Work←Work+Allocationᵢ`，记入安全序列。全完成则安全；若剩余任何进程都无法满足，写出此时 `Work` 和具体不足项，判不安全。
2. **给一个新请求，问能否立即给。** 先查 `Requestᵢ≤Needᵢ`（超过是错误）；再查 `Requestᵢ≤Available`（超出现有量只能等待）；均通过才试分配：`Available−=Requestᵢ`、`Allocationᵢ+=Requestᵢ`、`Needᵢ−=Requestᵢ`。用新矩阵跑第一类；安全就提交，不安全就回滚三项，让它等。

`Work` 是模拟变量，不是系统实际执行一轮就立刻修改的可用量。先暂借 `Need`、完成后返还 `Need+Allocation`，净增量恰是 `Allocation`。因此能完成的任选一个，不用为了找“唯一”答案回溯。向量比较逐列进行，不允许 A 类剩余抵消 B 类不足。

**安全 ≠ 当前没有死锁。** 安全状态承诺存在一种满足所有最大需求并完成的顺序；不安全是没有这种保证，不意味着现在已经死锁。检测当前死锁使用实际的等待请求，不直接用 `Max` 代替。

## 习题 3 第 22 题｜四套 Available

| 进程 | Allocation | Max | Need |
|---|---|---|---|
| P0 | (0,0,3) | (0,0,4) | (0,0,1) |
| P1 | (1,0,0) | (1,7,5) | (0,7,5) |
| P2 | (1,3,5) | (2,3,5) | (1,0,0) |
| P3 | (0,0,2) | (0,6,4) | (0,6,2) |
| P4 | (0,0,1) | (0,6,5) | (0,6,4) |

| 初始 Available | Work 轨迹（箭头标完成者） | 判断 |
|---|---|---|
| (1,4,0) | (1,4,0) —P2→ (2,7,5) —P0→ (2,7,8) —P1→ (3,7,8) —P3→ (3,7,10) —P4→ (3,7,11) | **安全**，所列顺序就是一个安全序列 |
| (0,6,2) | (0,6,2) —P0→ (0,6,5) —P3→ (0,6,7) —P4→ (0,6,8) | **不安全**。P1 缺 B（要 7），P2 缺 A（要 1）；交换已能完成的进程不能消除短缺 |
| (1,1,1) | (1,1,1) —P0→ (1,1,4) —P2→ (2,4,9) | **不安全**。剩余 P1/P3/P4 的 B 需求为 7/6/6，都超过 4 |
| (0,4,7) | (0,4,7) —P0→ (0,4,10) | **不安全**。P2 缺 A，P1/P3/P4 缺 B |

**自检：** 能全部模拟完成时，末 `Work` 应等于初始 `Available + Σ Allocation`，即真实资源总量。

## 教材 §3.7.2 例题｜试分配不是马上同意

书 p.101–102 / PDF 122–123，图 3-17 至 3-20。资源总量 (10,5,7)，初始 `Available=(3,3,2)`。

| 进程 | Max | Allocation | Need |
|---|---|---|---|
| P0 | (7,5,3) | (0,1,0) | (7,4,3) |
| P1 | (3,2,2) | (2,0,0) | (1,2,2) |
| P2 | (9,0,2) | (3,0,2) | (6,0,0) |
| P3 | (2,2,2) | (2,1,1) | (0,1,1) |
| P4 | (4,3,3) | (0,0,2) | (4,3,1) |

- 初始安全序列之一 `P1→P3→P4→P2→P0`。初始 Work 经 P1、P3 完成依次变 `(5,3,2)`、`(7,4,3)`，此时 P4 也能满足。
- P1 请求 `(1,0,2)`。两项检查都通过。试分配后 `Available=(2,3,0)`、`Allocation₁=(3,0,2)`、`Need₁=(0,2,0)`；可走 `P1→P3→P4→P0→P2`，准许。此后继续使用新状态。
- P4 请求 `(3,3,0)`：请求合法，但现有 A 只有 2，等待，连试分配都不做。
- P0 请求 `(0,2,0)`：两项检查都通过，但试分配后 `Work=(2,1,0)`，没有任何进程的剩余需求可满足；拒绝立即发放并回滚。
- **变式：** 若上一步 P0 只请求 `(0,1,0)`，在 P1 已获准后的状态中，试分配后 `Work=(2,2,0)`。P1 先完成后变 `(5,2,2)`，然后可走 `P3→P4→P0→P2`，所以**能分配**。
